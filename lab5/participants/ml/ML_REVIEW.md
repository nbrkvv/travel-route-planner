# Проверка индивидуальной ML-части ЛР5

## Область проверки

Проверены исходники ML ЛР1–4, общий L3_ml/L4_ml и runtime-сценарий, Python-прототип реестра из ЛР3. README и решения о количестве процессов/реплик не изменялись. Результат относится к ML-части; не закрывает известные замечания к frontend, защите main и командному review.

## Схемы и код

| Проверка | Результат |
|---|---|
| L3 рекомендаций | Четыре компонента: rec_api_comp, rec_inference_comp, rec_explainer_comp, rec_model_registry_comp; внутренние связи Python Call |
| Кэш | ModelCache — класс, принадлежащий ModelRegistry в UML L4; отдельный C4-контейнер или Redis не вводится |
| Загрузка | poll_once(): метаданные → проверка/резерв логической квоты → скачивание → проверка ModelLoader → admit_and_activate |
| Отказ MinIO | OFFLINE_CACHED только при наличии активной модели; объект остаётся пригоден для инференса |
| Холодный запуск | Без активной модели и доступного хранилища — ModelUnavailable |
| Неудачное обновление | Нехватка квоты, повреждённый артефакт и сбой загрузки не заменяют текущую модель |
| Strategy | FIFO, LRU и Priority заменяемы через set_cache_strategy; для вытеснения доступны только неактивные версии |
| Версии рендера | C4 2.12.0, PlantUML 1.2025.2; C4-схемы задают Smetana; UML L4 сохраняет исходный стиль |

В основной локальной динамике обращения к хранилищу отсутствуют: запрос использует RAM. Дополнительный model_update_ml показывает успешную загрузку до сбоя и обслуживание запроса после сбоя. Ответы синхронных операций возвращаются в рамках соответствующих вызовов.

## ML → backend: что установлено и что остаётся предложением

Источник проектного контракта — `lab5/contracts/project.json`, интерфейс `rank`: backend передаёт кандидатов с ID/признаками, интересы и контекст; получает ID, оценки, объяснения и model_version. Предложен `POST /v1/recommendations`, HTTPS/JSON, порт 8001. Точные JSON-поля, типы, ошибки и endpoint ещё не подтверждены работающим HTTP API.

Проверенный прототип реализует ModelRegistry, ModelCache, ModelLoader и эмулятор MinIO, но не сервис ранжирования, HTTP-контроллер и модуль объяснений. ModelRegistry.get_active_model() возвращает объект модели; отдельного публичного API выдачи метаданных выбранной версии в прототипе нет. Объект модели и метаданные одной версии на протяжении запроса — требование к будущему адаптеру, а не проверенное свойство конкурентного сервиса.

Диапазон score [0,1] относится к предложенному транспортному контракту: LinearModel.predict() — линейная сумма и сам диапазон не гарантирует (например, вес 0.8 при признаке 2.0 даёт 1.6). Перед объявлением сетевого контракта реализованным нужен согласованный способ нормализации/проверки и тесты API.

Fallback на базовую оценку категорий выполняет backend. Это предложенная политика деградации общего сценария, не успешный ответ ML-прототипа. При холодном запуске без модели успешный ML-скоринг не заявляется. Точный транспортный статус ошибки и обозначение fallback в ответе остаются для ревью backend.

Квота `2 × размер артефакта + 256` — логический резерв учебного прототипа. Реальный RSS, потокобезопасность, конкурентные запросы, checksum/подпись и реальная интеграция с S3 этими тестами не проверяются. Фактическая проверка загрузчика — размер и формат JSON/преобразуемость весов; полная версия схемы признаков в этом прототипе не валидируется.

## Воспроизводимые проверки

Добавлен `code/test_model_registry.py`: 11 поведенческих тестов, без сети и сторонних библиотек. Охвачены первая загрузка, отсутствие повторного скачивания, отказ хранилища, холодный запуск, отказ скачивания, повреждение артефакта, нехватка квоты, восстановление и три стратегии вытеснения. Подмена хранилища используется только для воспроизводимого отказа на границе download().

Из корня репозитория:

```sh
python -m unittest discover -s lab5/participants/ml/code -p 'test_*.py' -v
python scripts/validate_lab5.py --jar /path/to/plantuml-1.2025.2.jar --render
```

Тесты ML включены в существующий validate_lab5.py и поэтому запускаются в GitHub Actions. Этот скрипт проверяет 35 диаграмм lab5; ещё 10 исторических схем проверяются отдельным render_diagrams.py. Новая папка front_diagramms в этот охват не входит — это отдельное замечание общего аудита.

Синтаксическая компиляция, тесты эмулятора и успешная CI не подтверждают фактическую работу HTTP, TLS или командное согласование. Изменения реестра ЛР3 для прохождения тестов не потребовались. Окончательное принятие интерфейса и fallback требует ревью тимлида.
